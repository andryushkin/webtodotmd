### src/background/service-worker.ts

**Security & Permissions**
- **medium**: `chrome.action.onClicked` triggers auto-capture via `captureSignal` in session storage with no throttle – rapid clicks could spam content script injections.
- **low**: `openPage` uses `getUrlLocale()` derived from `chrome.i18n.getUILanguage()`, which is safe, but the resulting URL is not validated before creating a tab.

**Message Passing**
- **low**: `onMessage` handler for `OPEN_AND_CAPTURE` uses `sender.tab.id` without verifying that the sender is a valid content script (though MV3 ensures only own scripts can reach it). The error handling for asynchronous `sidePanel.open()` may leave the panel unopened silently.

**TypeScript Quality**
- **low**: `SUPPORTED_LOCALES` is defined as `Set<string>` with mixed undercore/hyphen‑cased values; the normalisation logic works but could be clearer by storing canonical forms.

**Storage API**
- No issues. Appropriate use of `session` for short‑lived signals and `local` for persistent translations.

### src/shared/settings-store.ts

**Security & Permissions**
- No issues.

**TypeScript Quality**
- **critical**: `getSettings()` spreads `settings` without a default value. When the extension is freshly installed and the key `settings` is absent, `chrome.storage.local.get('settings')` returns `{}`, making `settings` `undefined`. Spreading `undefined` throws a runtime error (`TypeError: undefined is not iterable`), crashing any call to `getSettings` (e.g., sidepanel `init()`).  
  **Fix**: `const { settings = {} } = await chrome.storage.local.get('settings');`.

**Storage API**
- No misuse; defaults are merged correctly once the undefined bug is fixed.

### src/sidepanel/sidepanel.ts

**Security & Permissions**
- **low**: `marked.parse` is called with `html: true` before DOMPurify; user‑controlled HTML (from the captured page) passes through Markdown parsing, but the sanitizer runs afterwards. The `escapeHtmlTagsInMarkdown` step adds an extra layer of protection, yet the order of operations could theoretically allow a crafted Markdown payload to inject HTML that survives both steps.

**Message Passing**
- **medium**: A `chrome.runtime.Port` (`highlighterPort`) is created for the highlighter feature, but no `onMessage` listener is attached. While the sidepanel doesn’t appear to await port messages (counts come via `chrome.runtime.sendMessage`), the port remains open and unhandled, which is a resource leak and could cause confusion if the content script ever posts to it.
- **low**: The `captureSignal` trigger uses a 3‑second window to handle a race between panel open and signal write. If the signal is delayed beyond 3 seconds, the auto‑capture is silently lost.

**TypeScript Quality**
- **low**: Multiple `!` non‑null assertions on DOM queries – safe if the HTML template is guaranteed, but a missing element would cause a runtime error.

**Performance**
- **low**: `renderMarkdown` (which involves regexes, `marked.parse`, and DOM sanitization) runs on every `input` event of the source textarea. On very large documents this could cause typing lag; debouncing is not implemented.
