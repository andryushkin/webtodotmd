### src/content/content-script.ts

#### Security & Permissions
- **Low**: Missing message sender validation in `chrome.runtime.onMessage` (no check on `sender.id`).  
  *Reason*: In practice Chrome isolates extension messaging, but best practice is to verify `sender.id === chrome.runtime.id` to avoid accidentally processing messages from a different version of the same extension or mis-routed ports. The `PING` handler does call `isContextValid()` which checks runtime ID, partially mitigating the issue.  
- **Low**: `OPEN_AND_CAPTURE` is sent via `chrome.runtime.sendMessage` without a callback – harmless, but silent failure if the side panel is closed.  
- No CSP violations or excessive permissions beyond those allowed by the extension.

#### Content Script Isolation
- **Low**: All injected UI elements (bubble, toast, highlighter overlays) use inline styles and unique IDs/classes (`tomd-bubble`, `s2md-shadow`, `s2md-highlighted`). Style conflict probability is low due to high specificity and `z-index`. No global pollution (module‑scoped variables).  
- **Low**: `expandShadowRoots` temporarily moves shadow content to light DOM; cleanup is in a `finally` block, but if the `try` throws before cleanup (unlikely), the wrapper is left. A more robust try‑finally ensures removal.  
- No shadow DOM leaks otherwise.

#### Message Passing
- **Low**: Handlers for synchronous operations (e.g., `CAPTURE_SELECTION`) return `true` even though `sendResponse` is called synchronously. This is technically incorrect but harmless – it keeps the message port open slightly longer than necessary.  
- **Low**: `CAPTURE_AND_COPY` correctly uses an `async` IIFE and returns `true` to keep the port open for the async clipboard write.  
- No race conditions or unhandled async responses.

#### TypeScript Quality
- **Medium**: Most function parameters and variables lack explicit types (rely on `any`). Examples: `(msg, _sender, sendResponse)` is untyped, many callbacks are `any`. This reduces the ability to catch shape mismatches at compile time.  
- **Low**: Manual null checks are present (e.g., `textNode.textContent?.includes('\n')`), but some places rely on implicit knowledge (e.g., `el.shadowRoot` guarded by `if`). The `as Text` cast in the tree walker is safe given `NodeFilter.SHOW_TEXT`.

#### Storage API
- No issues. `chrome.storage.local` is used correctly for persistent settings and translations. No quota concerns.

#### Performance
- **Low**: `selectionchange` listener runs on every selection change; early‑out checks are fast.  
- **Low**: `expandShadowRoots` traverses all elements with shadow roots only during capture, not on every page load.  
- No memory leaks: `selfDestruct` removes all event listeners when the extension is unloaded; bubble element is reused.

### src/sidepanel/sidepanel.ts

#### Security & Permissions
- **Low**: Side panel is an isolated extension page. No CSP violations – all dynamic content is sanitized via `escHtml` or `DOMPurify`. `innerHTML` usage for status and preview is properly escaped/sanitized.  
- **Low**: No message sender validation (the `HIGHLIGHT_COUNT` listener). In practice only extension‑internal messages are received.  
- **Low**: External URLs are opened via `chrome.tabs.create` (rating CTA), safe.

#### Content Script Isolation
- Not applicable (side panel is not injected into content pages).

#### Message Passing
- **Medium**: Rapid capture clicks (manual or via `captureSignal`) can cause out‑of‑order `rawMd` updates. The content of two nearly‑simultaneous captures may be appended in the order responses arrive, not in the order requests were made. No queuing or locking is implemented.  
- **Low**: `sendMessageWithTimeout` provides a timeout wrapper, avoiding stalled async responses.

#### TypeScript Quality
- **Low**: Good usage of defined types (`CaptureResponse`, `PageMeta`).  
- **Low**: Some callbacks still use implicit `any` (e.g., `sendResponse` in `chrome.tabs.sendMessage`), but overall stricter than the content script.  
- Few non‑null assertions (`!`) on DOM elements – acceptable because the HTML structure is guaranteed.

#### Storage API
- No issues. `chrome.storage.local` for persistent data, `chrome.storage.session` for transient signal (`captureSignal`). No misuse of quota.

#### Performance
- **Low**: `preprocessMath` regex runs only when content changes, not on every render. `marked` + `DOMPurify` + KaTeX per update is typical.  
- **Low**: `undoStack` capped at 50, preventing memory bloat. The rating widget’s event listeners are never removed, but the side panel has a long lifetime where this is acceptable.
