What each of us got wrong

Case K4: A <mark>marked phrase</mark> beside literal comparisons x==y and C==C++.

Obsidian

A ==marked phrase== beside literal
comparisons x==y and C==C++.

The highlight is right; the page's own == are not escaped, so a renderer that knows the marker paints “y and C” yellow — a highlight nobody made.

Ours, before this week

A ====marked phrase==== beside literal
comparisons x\=\=y and C\=\=C++.

Escaping right, marker doubled: the browser paints <mark>, so the style snapshot reported a fill on the one tag whose rule already writes ==. Fixed in b846e8b, with the case in core/tests/inline.test.ts.

How to read these numbers

One page, one run. It is our own specification page, which we wrote — so it asks the questions we already know to ask. It says nothing about pages neither of us has seen.
Obsidian Web Clipper is built around Readability: it takes the article it detects rather than the selection. On this page that is a different promise, not only a different result, and part of what is counted as “kept” or “lost” follows from it.
Counted mechanically from the two saved files. “Inline formulas” is left off the tiles because a price like $129.00 counts as one on both sides — a metric that measures the counter, not the clipper.
