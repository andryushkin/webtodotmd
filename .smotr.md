# smotr — memory for webtodotmd

## Connection
`.smotr.json`: contentDir `docs`, port 8010, `skipDirs: ["invariants"]` (the
invariant sheets are law, not artefacts to mark up). Launcher:
`docs/review/run`. Engine stays in `~/Server/smotr`.

## Design tokens
`src/sidepanel/sidepanel.css:8` — the panel's own custom properties: `--bg`,
`--bg-secondary`, `--bg-code`, `--text`, `--text-muted`, `--border`,
`--accent: #0066cc`, status colours, `--radius: 6px`, Inter + Menlo. Prototypes
take their palette from there so a reviewed screen reads as the product.

The store's staging pages are a different look on purpose (own template in
`~/Server/dotmdtools/templates/shot.html`) — do not unify them with the panel.

## Design folder
`docs/design/`.

## Conventions
- One file = one screen. Everything written in the repo is in English.
- Numbers on a prototype carry their source; a claim without a measurement
  beside it is the thing this project treats as a defect.

## Prototype inventory
- `slide-5-why.html` — mock-up of the fifth Chrome Web Store tile, on a fixed
  1280 × 800 canvas, to be redrawn in a layout tool. Draft, awaiting review
  (2026-07-29).
- `clipper-comparison.html` — where the numbers on that slide come from: Text
  to .md against Obsidian Web Clipper on the spec page, both ⌘A. Working
  document, not a deliverable (2026-07-29).

## Decisions / recurring feedback
- Nothing on a comparison page that we cannot re-derive from the two saved
  files; caveats stay on the page, not in a footnote nobody reads.
